# KITECH ARCHITECTURE SPECIFICATION (KITECH_ARCH_SPEC.md)

## Executive Summary

KITECH adalah Sovereign Industrial-Grade Ecosystem berbasis Rust yang dirancang untuk otomasi infrastruktur Telco, ISP, dan Enterprise. Fokus utama adalah modularitas tinggi, performa deterministik, dan zero-human intervention dalam operasional serta pengembangan.

## Core Foundation (kit-core)

kit-core adalah library wajib (base crate) yang harus diimpor oleh semua produk KITECH.

### Actor Kernel

* Engine: Menggunakan tokio sebagai async runtime.
* Pattern: Actor Model untuk isolasi state setiap entitas (User/ONT/Device).

* Lifecycle: Setiap actor harus mengimplementasikan trait Actor { async fn start(); async fn stop(); }.


### Protocol Abstraction Layer (kit-protocol)

* Trait-based Design: Setiap protokol harus mengimplementasikan ProtocolHandler trait.
* Standard Interface:
                 Request -> ProtocolHandler -> DomainEvent.
                 DomainEvent dikirim melalui Event Bus sentral.



### Infrastructure Providers (The "Zero-Hardcoding" Rule)

Setiap aplikasi dilarang memanggil database secara langsung. Gunakan Traits:

* StorageProvider: Untuk persistence (PostgreSQL/SurrealDB/MongoDB).
* CacheProvider: Untuk high-speed state (DragonflyDB).

* MessageProvider: Untuk inter-service messaging (Redpanda/RabbitMQ/NATS).
* Implementasi ditentukan pada runtime melalui config file.



### Distributed State & Scalability

* **Stateless by Design**: Aplikasi harus stateless. Semua shared state (session, status) disimpan di CacheProvider (DragonflyDB).
* Consistency: Menggunakan Saga Pattern untuk transaksi lintas database (diatur oleh kit-core).

* Scaling: Mendukung Distributed Shared-State. Node baru dapat bergabung ke cluster tanpa downtime dengan mekanisme Actor Migration.



### Observability & Telemetry (Unified Stack)

1. Unified Tracing: Semua event wajib menyertakan trace_id (OpenTelemetry).
2. Log Processing: Semua log dikirim ke vector.dev (local collector).
3. Log Storage:
   Quickwit untuk full-text search.
   ClickHouse untuk long-term analytical query.

4. Metrics: Integrasi penuh dengan Prometheus/Grafana melalui standar OTel.



### Development & Autonomous Evolution

#### The "Evolve" Protocol

Untuk memodifikasi kit-core, agen AI harus mematuhi siklus:

1. Requirement: Baca KITECH_ARCH_SPEC.md.
2. Implementation: Refactoring/Coding di feature-branch.
3. Verification:
   cargo test (Unit/Integration).
   kani (Formal Verification untuk logika telco).
   clippy (Standard compliance).
4. Shadow Deployment: Deployment ke Shadow Environment untuk verifikasi telemetry.
5. Merge: Otomatis jika semua tes hijau.

#### Formal Verification

Logika krusial (konfigurasi OLT, perhitungan AAA, routing logic) wajib diuji dengan Kani Rust Verifier untuk memastikan tidak ada integer overflow atau panic saat kondisi edge case telco.

### Deployment & Operations

* Orchestration: Docker + Dokge (Declarative).
* Policy Engine: Open Policy Agent (OPA) sebagai "Circuit Breaker".

* Secrets: HashiCorp Vault (Dynamic secret injection).
* High Availability: Keepalived untuk virtual IP dan redundansi baremetal.

### AI Intelligence Module (kit-ai-engine)

* Sidecar Approach: AI sebagai fitur (seperti anomaly detection) diimplementasikan sebagai feature-gated crate.
* Inference: Menggunakan mistral-rs sebagai local inference engine via UDS (Unix Domain Socket).

* Model Management: Model dikelola sebagai artifact terpisah, bukan dalam source code.



### Development Standards (The "Golden Rules")

No unwrap(): Gunakan Result dan Option secara eksplisit.

Dependency Control: Setiap penambahan dependensi baru harus disetujui melalui audit.

Documentation: Setiap modul harus memiliki dokumentasi /// yang machine-readable untuk membantu AI memahami fungsi tersebut.

Interface First: Definisikan trait sebelum menulis implementasi.
